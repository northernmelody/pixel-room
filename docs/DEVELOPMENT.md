## 1. 产品定位与范围

Pixel Room 是一个按北京时间运转的横向剖面像素生活场景。用户主要观察人物和宠物的日常，点击少量物件触发反馈、阅读内容或临时活动。天气、季节、光照、环境音和跨日小物件让同一个房间随时间变化。

当前核心体验闭环：打开场景 → 观察当下生活 → 点击人物、宠物或物件 → 获得动画、文字或声音反馈 → 角色恢复日常 → 在其他时刻或日期再次发现变化。

当前不是完整的经营或任务制游戏：没有玩家移动控制、背包、货币、商店、装修编辑、任务领取、任务奖励、等级、成就、胜负或通关。本文将角色自动执行的行为称为“生活流程”，与未来可能增加的游戏任务区分。

| 项目 | 当前事实 |
| --- | --- |
| 在场人物 | 1 位未命名生活主角；短紫发女友晚间到访、留宿并于次日早晨离开 |
| 叙事人物 | MOMO 仍通过聊天屏和两封信出现；历史通话内容保留但不再进入竖版正式作息 |
| 活体宠物 | 1 只橘猫、1 只棕色腊肠狗 |
| 房间 | 卧室、工作区、卫生间、厨房，共 4 间 |
| 门区 | 厨房右侧新增户外木门，只展示及提示，未开放出门 |
| 内容数据 | 100 组通话、2 封信、38 个餐食条目、6 种零食、3 首原创歌词歌曲 |
| 可识别玩偶 | 墙面 6 个，加床上腊肠狗抱枕，共 7 个 |
| 灯具 | 4 盏顶灯、工作区台灯、卧室床头灯，共 6 盏 |
| 技术形态 | 原生 JavaScript、Canvas 2D、CSS、DOM 覆盖层、WebAudio |
| 数据 | 本浏览器 localStorage，无账号、服务端数据库或云同步 |
| 外部依赖 | 北京天气通过 Open-Meteo 获取；剧情与像素主体不依赖在线生成 |

## 2. 场景、布局与坐标

### 2.1 当前画布

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `CANVAS_W × CANVAS_H` | 1376 × 544 | 主画布内部尺寸 |
| `LOGICAL_W × LOGICAL_H` | 344 × 136 | 场景逻辑像素 |
| `PIXEL` | 4 | 逻辑坐标到内部画布的倍率 |
| `SKY_H` | 24 | 天空区域配置 |
| `CEILING_Y` | 30 | 天花板下沿 |
| `FLOOR_Y` | 124 | 当前地板基线 |
| `LEGACY_FLOOR_Y` | 128 | 角色与旧家具行为基线 |
| `GROUND_Y` | 136 | 底部材质切面终点 |
| `DOOR_Y` | 78 | 房间分隔门洞视觉顶部 |

从左到右，区间按左闭右开理解：

| 房间 ID | 中文 | 起点 x | 宽度 | 横向区间 | 旧坐标平移量 |
| --- | --- | ---: | ---: | --- | ---: |
| `bedroom` | 卧室 | 0 | 76 | [0, 76) | 0 |
| `workspace` | 工作区 | 76 | 92 | [76, 168) | -4 |
| `bathroom` | 卫生间 | 168 | 68 | [168, 236) | +8 |
| `kitchen` | 厨房 | 236 | 108 | [236, 344) | -4 |

布局并非把四个房间统一缩放：家具保留像素尺寸，横向按房间起点平移。`Config.mapLegacyX()` 将旧版四个 80px 区域映射到新房间；`ROOM_WIDTH=80` 仅用于旧坐标兼容，不能再拿来计算显示布局。

角色和落地家具绘制时统一应用 `124 - 128 = -4px` 的纵向位移；墙面挂件、窗和户外门有各自绘制规则。修改坐标时必须同时核对绘制、行为站位、光照遮挡和点击区域，不能全部无差别加偏移。

主场景随窗口等比适配，预留约 24px 外边距，CSS 宽高按 4px 对齐。关闭 Canvas 平滑以保留像素边缘。没有场景拖动、相机缩放或房间切换控制。

### 2.2 卧室

视觉以暖色墙面、木地板和地毯为主，负责睡眠、阅读、手机、看窗外、弹唱、换衣和通话。

| 对象 | 当前用途及变化 | 用户直接操作 |
| --- | --- | --- |
| 床、枕头、被子 | 睡眠和床边坐姿；被子按时间切换盖身、铺好、凌乱 | 不提供整理床铺按钮 |
| 衣柜 | 角色换衣时打开双门，显示内部衣服，再关闭；猫可到柜顶 | 休闲时点击可触发换衣 |
| 床头柜、床头灯 | 卧室局部暖光 | 灯可开关 |
| 窗、窗帘、窗台 | 昼夜天空、光照、季节窗花/霜；猫会抓窗帘 | 无手动开窗、拉窗帘 |
| 吉他 | 墙边摆放，取走时隐藏，归还时恢复 | 点击触发完整弹唱 |
| 墙钟 | 场景装饰 | 无设置时钟功能 |
| 墙面玩偶 | 两排，每排三个：奶茶、牛油果、小兔、橘子、小章鱼、拉面 | 悬浮名称；点击提示名称 |

| 夏季空调、冬季暖气 | 随季节显示 | 无独立设备控制 |

旧 `frames` 数组目前为空，墙面主要留给玩偶；不能因为存在挂画绘制代码就认定默认展示了旧版多幅挂画。

### 2.4 卫生间

采用浅色上墙瓷砖、深色防水墙裙、圆镜、毛巾和浅蓝瓷砖地面。基本设备是淋浴区、花洒、洗手台和马桶。

早晨执行如厕、冲水、洗手和刷牙；晚上执行淋浴；夜间可起夜。冲水有音效，洗手/淋浴有对应角色动作和水效果。设备目前由角色行为驱动，不能点击马桶或水龙头直接安排任务。

`FURN.bathroom.cabinet` 和 `drawBathCabinet()` 仍留在代码中，但当前中景绘制不调用卫生间吊柜，原因是缩窄后避免重叠。应视为保留代码，不计入当前可见家具。

### 2.5 厨房及门区

采用米白小方砖上墙、深绿色护墙板及红棕棋盘格地砖。

| 对象 | 当前用途及变化 | 用户直接操作 |

| 吊柜 | 家具及猫的攀爬支撑面 | 点击显示当前餐食信息，并非开柜 |

| 绿植 | 季节外观 | 无浇水或成长值 |

## 3. 人物与生活流程

### 3.1 主角定义

主角具有暖色皮肤、棕色头发、按季节和“自由职业日”变化的服装。当前未提供姓名、性别、年龄、职业档案或玩家自定义编辑。不要从外观或对白推导未定义的角色设定。

主要状态包括：`activity` 作息大类、`pose` 当前姿势、`x/target/moving/dir` 移动状态，以及餐食、洗漱、休闲、夜间、换衣/零食、吉他和短时反应的子状态。

移动主要沿地板横向进行，常规速度 15 逻辑像素/秒；不是自由寻路或物理碰撞系统。初始化时直接放在当前作息对应位置，后续活动切换通常走向目标。

### 3.2 每日时间表

以下均为北京时间，区间不包含结束时刻。周末和普通工作日共用这张时间表。

| 时间 | ID | 活动 | 主要位置 |
| --- | --- | --- | --- |
| 00:00–07:30 | `sleep` | 睡眠，可发生起夜 | 卧室 |
| 07:30–08:00 | `wash` | 如厕、冲水、洗手、刷牙 | 卫生间 |
| 08:00–08:30 | `breakfast` | 早餐 | 厨房 |
| 08:30–12:00 | `work` | 工作及屏幕动画 | 工作区 |
| 12:00–13:00 | `lunch` | 午餐 | 厨房 |
| 13:00–18:00 | `work` | 工作 | 工作区 |
| 18:00–19:00 | `dinner` | 晚餐 | 厨房 |
| 19:00–21:30 | `leisure` | 随机休闲 | 多房间 |
| 21:30–22:00 | `call` | 与 MOMO 通话 | 卧室床边 |
| 22:00–22:30 | `wash` | 淋浴 | 卫生间 |
| 22:30–24:00 | `sleep` | 睡眠，可发生起夜 | 卧室 |

“自由职业日”：周末固定成立，工作日由日期种子和阈值判定；源码注释标注 40%，不是每次打开随机抽取。它影响衣服、电脑绘画模式以及工作中起身喝水，不意味着人物不上班或出门。

### 3.3 洗漱

早晨链路：走到马桶 → 如厕约 4–6.5 秒 → 冲水 1.3 秒 → 走到洗手台 → 洗手 4.5 秒 → 刷牙，持续到下一作息。洗手动作包含开水、搓洗、关水和毛巾表现。晚间直接进入淋浴流程，不重复早晨整条链。

### 3.4 三餐

链路：`go → open → cook_go → cook → serve → done`。

1. 到冰箱左侧取食材，打开约 2.2 秒，门开始和结束各约 0.35 秒过渡。
2. 走向灶台，烹饪约 7–10 秒。
3. 走回餐桌，食物阶段标记为 `eat`，保持吃饭到作息切换。

食物来自日期确定的菜谱，不是每次刷新随机：`(dayNumber × 7 + salt) mod 菜单长度`，早餐/午餐/晚餐盐值为 3/17/31。菜单类型决定像素表现，同类菜名共用绘制，不是 38 套独立美术。

所有餐食均走统一的取材和烹饪链，包括名称为外卖的菜；没有真实食材库存、下单配送、烹饪失败、饥饿值或营养系统。

### 3.5 工作

人物坐在电脑前，屏幕计时切换。初始化间隔为 8–20 秒，之后为 8–22 秒；非摸鱼画面会触发键盘音。自由职业日可起身走到厨房喝水，再回电脑，停留约 4–7 秒。

电脑表现详见第 6 节；写代码、绘画和游戏均为场景动画，不产生文件、画作存档或玩家可控制的游戏结果。

### 3.6 休闲活动

| ID | 活动/地点 | 基础权重 | 动作细节 |
| --- | --- | ---: | --- |
| `game` | 工作区打游戏 | 20 | 电脑切至 `game`，人物游戏姿势 |
| `read` | 床边看书 | 18 | 阅读 3–5 秒后翻页约 0.5 秒 |
| `exercise` | 工作区健身 | 26 | 深蹲、俯卧撑、开合跳，每 30–60 秒换动作 |
| `play_cat` | 工作区逗猫 | 16 | 挥动逗猫棒，猫追逐、扑跳、休息 |
| `look_out` | 卧室看窗外 | 7 | 看窗外与抬头，抬头约 1.5 秒 |
| `phone` | 床边玩手机 | 18 | 坐、仰躺、趴姿；变姿先坐起约 0.6 秒 |
| `snack` | 厨房拿零食 | 12 | 独立取物、进食、返回流程 |
| `change` | 卧室换衣 | 7 | 独立开柜、换衣、关柜、返回流程 |

权重不是百分比，会按候选总和重新归一。下一项排除当前活动；猫睡觉时排除逗猫，并给阅读和手机各加 8。21:00 后健身权重降至 12；代码还保留 21:30 后权重 5 的分支，但正常作息此时已进入通话。21.45 是十进制小时，即 **21:27**，此后随机选择不再新增零食和换衣。

普通休闲每项 5–20 分钟；看窗外 10–30 秒。`?leisurefast` 将这两类总时长乘 0.02，不是整个世界或所有子流程统一加速。

零食：走向冰箱 → 取物约 1.6 秒 → 走到餐桌 → 吃 22–38 秒 → 返回休闲。每日零食按日期索引选择，完成后自动选择冷却 90 分钟。

换衣：走向衣柜 → 开门 1.4 秒 → 换衣 4.5 秒 → 关门 1 秒 → 返回休闲。完成后 `outfitIndex` 在 0/1/2 循环并存档，自动选择冷却 180 分钟。索引 0 使用季节/日期服色，索引 1 为橘色上衣，索引 2 为蓝紫上衣。

手动 `startChange()` / `startSnack()` 会检查是否休闲、是否已有 life 流程、是否弹唱，但不检查上述冷却；冷却目前只限制随机活动选择。UI 仅为衣柜接入手动入口，`startSnack()` 只是可调用 API。

### 3.7 夜间活动

进入睡眠后生成内存中的本夜计划：70% 不发生夜间活动，其余生成 1–3 次。活动窗口约 23:12 至次日 06:48，相对 22:30 的经过分钟数比较，支持跨零点。

| 类型 | 相对权重 | 到达后的持续时间 |
| --- | ---: | --- |
| `toilet` 如厕 | 20 | 45–90 秒 |
| `drink` 喝水 | 15 | 30–70 秒 |
| `snack` 夜宵 | 10 | 60–120 秒 |
| `phoneToss` 手机/翻身 | 30 | 120–300 秒 |

如厕、喝水、夜宵结束后回床；手机/翻身留在床上。起床时夜间计划作废。夜宵是夜间简化行为，不等同于休闲零食的完整生命周期。计划不持久化，刷新可能重新生成；不应承诺跨页面保持同一夜剧情。

### 3.8 点击人物

随机出现挥手 `wave`、点头 `nod`、惊讶 `startle`、回头 `lookback`，持续约 1.2–1.8 秒，短暂停住当前更新。睡觉和淋浴姿势不响应。快速闪灯还能指定 `lookup` 抬头反应。

## 4. 宠物系统

### 4.1 橘猫

当前固定橘色条纹配色。存档中的 `catSeed` 是兼容残留，不代表可选 5 种猫。刷新时从卧室、工作区、厨房常见落脚点随机出生。

| 状态 | 表现/规则 |
| --- | --- |
| `idle` | 发呆，通常 1–3.5 秒 |
| `wander` | 在人物附近或常见区域游走，通常 8px/秒 |
| `groom` | 理毛约 3–7 秒 |
| `sleep` | 睡觉约 8–22 秒；人物选择休闲时会避开逗睡猫 |
| `zoomies` | 短时狂奔约 0.8–2 秒，30px/秒 |
| `rub` | 接近人物并蹭人 |
| `climb / perch / jumpdown` | 走近家具、跳上、停留、跳下，含弧线和落地挤压 |
| `scratch` | 走向卧室窗帘后抓挠 |
| `underbed / crawlout` | 走到床下躲藏，主要露出尾巴，然后爬出 |
| `eat` | 到猫粮碗吃约 2.5–4.5 秒，每次消耗 1 份 |
| `pet / walkaway` | 点击反馈；连续摸多次后离开 |
| `flee` | 受惊后跑向最近床下或柜顶隐蔽点 |

## 7. 时间、天气、灯光、声音

### 7.1 时间源

北京时间基于系统时间加 UTC+8 偏移，本地时间只用于显示。日期用于每日内容、天气兜底、灯光覆盖和物品跨日。

`?t=HH:MM[:SS]` 改变起始模拟时刻，之后仍按现实经过秒数前进，**不是冻结时间**。只覆盖时分秒，不修改真实北京日期；模拟时刻绕过午夜时，日期不会同步虚拟推进，不能用于完整跨日验收。

季节按月份：3–5 春、6–8 夏、9–11 秋、12–2 冬。日出日落是季节固定近似值：春 06:00/18:12，夏 05:12/19:24，秋 06:12/18:00，冬 06:48/17:12，不是实时天文服务。太阳/月亮、星空、云与暮光按该模型绘制。

### 7.2 天气

北京坐标固定为纬度 39.9042、经度 116.4074，取温度、天气代码、降水和风速。支持晴、多云、阴、雾、雨、雪、雷雨 7 种状态，联动天空明暗、粒子和环境音。

启动先用确定性中性占位天气，永不降水；请求成功标记 `api`，失败后按日期散列生成 `fallback`。请求超时 7 秒，成功缓存目标 30 分钟，失败退避 5 分钟，底层请求最短间隔 15 秒。主循环低频尝试刷新，因此不是精确到点轮询。

兜底：夏季雨阈值 0.18，其余季节 0.13；冬季雪区间长度 0.22，其余季节 0.11。因此当前离线规则存在非冬季下雪的可能，不是现实气象模拟。天气明暗、风和音效也不是房间热力或空气流动计算。

### 7.3 灯光

窗光是白天主要来源，夜间为各房间顶灯与局部灯光。四盏顶灯各有色温、半径和强度；叠加局部表面受光、窗格/家具遮挡、屏幕冷光和暗角。

默认自动模式：卧室顶灯不自动亮；其他顶灯和工作台灯在夜间且非安静时段亮；床头夜灯可在晚间至当日随机关灯时刻点亮。安静时段为 23:00 后及 07:30 前。

手动点击写 `lamps.touched/touchedDate`，当天采用存储灯状态，影响的是整套灯状态判断，而非每盏灯独立记录手动策略。跨日清除覆盖，恢复自动模式。

自动检查仍会在 23:00 后关闭非卧室灯；卧室顶灯和床头灯在每日随机 23:00–24:00 时刻关闭。人物连续处于睡眠姿势、记录入睡时间超过 5 分钟时，另关闭已开启的卧室顶灯。手动开灯不会无条件覆盖这些自动关闭检查。

### 7.4 声音

默认静音、默认音量 60。WebAudio 以振荡器和噪声合成，按交互启用音频上下文。环境层包括雨、风、白天鸟鸣、夜间虫鸣；交互音包括 UI、灯开关、猫叫、呼噜、狗叫、键盘、雷声、进食、冲水和吉他。

`footstep()` 有定义，但没有据此证明普通移动已逐步触发脚步音。音乐与通话均不依赖人声文件。环境音昼夜用 06:00/19:00 阈值，与季节日出日落模型不是完全同一个边界。

### 9.2 调度与打断约束

通话边界先于吉他推进检查；人物短时点击反应会暂停后续主角状态更新；吉他使用专用更新并暂停常规日程；其余才进行作息切换和子状态推进。猫和狗各自独立更新，不会随主角反应整体暂停。

当前是多套相互调用的状态机，不是具有统一取消/恢复语义的任务队列。未来添加动作应明确：触发条件、目标位置、进入阶段、持续时间、道具持有状态、取消策略、恢复策略、存档策略以及验收方法。尤其关注 21:30/22:00/22:30 边界以及弹唱打断取零食、换衣、做饭等组合。

主循环顺序：跨日/物品同步 → 主角 → 自动灯光 → 猫 → 狗 → 天气粒子 → UI → 低频音频/天气 → 渲染。后台恢复时 `dt` 截断为最多 50ms，不补齐所有离线动作；作息和日期重新按时钟读取。

渲染顺序：天空 → 静态房间缓存 → 动态家具 → 主角 → 猫 → 狗 → 天气粒子 → 室内光影 → 电脑弹窗画布。不是按实体 y 值自动深度排序。

静态缓存签名包含季节、有效灯状态、动画设置、咖啡、被子、两种宠粮、水槽碗、快递、收藏、食物类型、猫停留点、吉他取走状态。新增影响静态画面的状态应进入签名，否则可能数据已改而画面不刷新；纯逐帧动态内容不必每帧重建缓存。

已有事件：`weather-change`、`sound-change`、`lamp-toggle`、`cat-pet`；事件总线捕获监听异常，不提供事件持久化。
